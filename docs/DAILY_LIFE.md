# 日常手记、可编辑笔记与个人空间

这一轮扩展把 NEXUS 从会话演示推进为可填写的日常工作空间：记录一段文字、保存主动选择的图片、安排一件事、留一段专注时间。它采用更简洁的卡片、柔和强调色和短过渡，保留独立的全息人物网络。网站内容在本浏览器处理，Android 原型加载内置网页并接入设备本地日程通知；没有图片上传、OCR、远端通知或医疗功能。

## 八种界面语言

打开设置页，在语言列表选择：**简体中文、繁體中文、English、Tiếng Việt、日本語、한국어、Español、العربية**。列表按每种语言自己的写法显示，阿拉伯语界面采用从右向左排版。语言偏好随工作空间保存；关闭“记住工作空间”后不保存本轮内容与语言更改。

切换的是导航、按钮、状态说明和表单文案。人物姓名、历史转写、示例笔记、关系引文和用户写下的文字保持原样，不自动调用翻译服务。因此英文界面中仍可能看到中文示例内容。

## 设置顶部的个人资料

设置页顶部提供自己的头像与姓名卡片，支持更换或移除头像、修改显示姓名并保存。名称不能为空、最多 40 个字符；头像支持 JPG、PNG、WebP，单张最多 2 MiB。上传表示从本机主动选图，不发送至云端。

个人资料以人物 ID 保存，自己的姓名会同步用于个人空间和人物网络；不会改写历史引文。头像附件与笔记图片采用相同的本地存储与删除机制，没有自动裁切、美颜、人脸识别或云端头像服务。

## 修改人物名称和备注

从人物网络或会话参与者打开档案。在“编辑人物资料 / Edit profile”中修改名称、添加备注，再保存。

- 名称不能为空，最多 40 个字符；备注最多 2,000 个字符。
- 显示名称与人物 ID 分开保存，改名会更新档案、列表与图谱中的名称，不会破坏已有关系引用。
- 备注可写称呼、共同项目或下次想聊的话题；它是用户主动输入的资料，不是系统推断。
- 改档案不会重写历史转写或关系证据中的原话。关系标签的修正仍使用独立的关系选择入口。

当前仍只有示例人物及其演示身份，不提供真实声纹识别、通讯录导入或自动发现现实人物。

## 会话名称与录音笔记编辑

打开会话详情中的“编辑会话与笔记”，可为课堂、会议或对话更改显示名称，并修改摘要、核心要点、决策、知识点与待办。要点按每行一项编辑；空行保存时会清理，待办可增加或移除。会话标题不能为空，最多 120 个字符。

“我的补充”可写自己的理解、会后记录或其他文字，并添加最多 4 张图片，每张不超过 2 MiB。附图可从会话详情单独下载。编辑器保存后使用用户修改的内容，结构化笔记标记为用户编辑，不再把它当作未经修改的规则输出。

原始示例转写及关系引文保持完整，用户编辑不会覆盖其原话，也不会产生新的 ASR 结果。当前没有笔记修改版本历史或撤销恢复服务，保存前可先导出需要的内容。此处的“录音笔记”属于会话记录；真实原始音频采集尚未接入。

## 写文字与照片手记

进入“日常手记 / Daily journal”，选择“写一篇手记 / New note”。输入标题和正文，可添加照片，保存后在卡片中查看；点击已有手记继续编辑。列表按更新时间排序，可按文字搜索或只看照片笔记。

空标题可使用默认名称；标题、正文和照片都为空时不能保存。正文是普通文本，没有富文本编辑、OCR、自动摘要或图像理解。

照片支持 JPG、PNG、WebP，每张不超过界面标示的 2 MB（实现阈值为 2 MiB），每篇最多 4 张。不支持 HEIC、视频或任意附件；需要先在设备上转换为支持的图片格式。没有自动压缩或去除照片元数据的承诺。

“上传照片 / Add photos”实际打开本机文件选择器，并将图片存于本浏览器；不会发送到远端。“拍照/选图 / Camera / photos”使用文件输入的 `capture="environment"` 提示，在支持的手机上由系统提供相机入口；桌面或不支持的浏览器可能只显示文件选择器。这不是应用内实时摄像头，也不会自动拍照。[文件选择器的 capture 属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)

点击照片可查看并单独下载。手记支持导出 `.txt`，只导出标题和正文；工作空间 JSON 只含文字、元数据及 `photoIds`，不包含照片二进制。需要完整备份时请单独下载照片。删除手记时关联附件也应随记录清理；浏览器清理及存储失败仍可能导致内容丢失。

## 日历安排与提醒

在“接下来的安排 / Coming up”中新建事件，填写名称、未来开始时间和预计时长。当前输入、日期展示采用北京时间 UTC+8；导出使用 UTC 时间点，接收日历会按自身时区显示。请在导入后核对时间。

当前支持创建、查看和删除事件，按实际时间排序；到期事件标为“已提醒 / Reminded”。这是提醒处理状态，不等于任务已经完成，也不是日历同步回执。没有重复规则、邀请参与者、会议室预订、双向同步或手机日历读取。

提醒有三种不同层次：

1. **页面内提示：**网页运行期间检查到期事件并显示提示。不需要浏览器通知权限。浏览器休眠、节流或关闭可能延迟或阻止检查。
2. **本设备浏览器通知：**只有用户点击“允许本设备浏览器通知 / Enable browser notifications”后才请求权限。需要支持的浏览器、安全上下文以及系统允许。拒绝或不支持时保留页面内提示；它不是手机后台推送。
3. **ICS 导出：**点击“手机日历 / Calendar”下载文件，再由用户自行导入手机或桌面日历。文件带开始时刻的显示提醒，但日历软件可能忽略导入的提醒，设备权限、静音和通知设置也会影响展示。

网站没有 Service Worker 推送服务或关闭网页后持续工作的后台进程。大多数移动浏览器也不支持页面直接创建桌面通知；不能因为授权成功就承诺手机锁屏后一定提醒。[Notifications API 限制](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API)

**Android APK 是单独的提醒路径：**应用内置原生 AlarmManager 与通知桥，用户主动授权后可把日程交给系统调度，并恢复重启后尚未到期的日程。精确闹钟权限不可用时会使用可能延迟的调度。通知权限、渠道关闭、系统强行停止与厂商省电限制均会影响结果；原生代码存在不等于已完成手机验收。安装与验证说明见 [交付说明](DELIVERY.md) 和 [Android 工程说明](../android/README.md)。

ICS 使用 `VALARM`、`ACTION:DISPLAY`、`TRIGGER:PT0S`，表示事件开始时的显示提醒；这只是标准文件中的请求，实际交付由接收日历负责。[iCalendar / RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html)

## 专注计时

选择 15、25 或 45 分钟，开始、暂停、继续或重置。倒计时以开始后的墙上时间差计算，避免只凭回调次数递减；完成后显示休息提示并累加工作空间中的完成分钟数。

计时状态在当前网页内存中运行，页面导航时可继续；刷新、关闭网页或浏览器终止后不保证保留或完成提醒。设备时钟改变也可能影响墙上时间计算。它不是可靠的系统闹钟，也不提供应用屏蔽、注意力监测或医学效果。

界面以“按自己的节奏”提供帮助，不要求连续打卡。未完成或暂停不代表失败。

## 本地保存与照片隐私

文字、日历、偏好与人物资料存于 `localStorage`；图片 Blob 存于同一站点的 IndexedDB。图片引用和文件分开保存，避免把二进制转成超长 JSON；IndexedDB 仍受浏览器配额、清理和站点来源限制，不是备份或应用级加密。[IndexedDB API](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

关闭“记住工作空间”会移除内容保存副本，并保留一个不含正文的保存关闭标记。照片可在当前页面内存中继续显示，但磁盘中的本地附件副本会清理；刷新后本轮输入不再保留，保存设置保持关闭。重新开启保存才会将当前工作空间写回本机。

同一浏览器配置中的使用者、站点脚本或有权限的扩展可能访问这些内容。照片可能含拍摄位置等元数据；当前没有自动清除元数据或加密机制。请对输入内容和导出文件保管作出自己的选择。

录音、转写和模型能力仍遵循原有边界：模拟会话不采集麦克风，合成提示音不是日常录音，真实 ASR、人物识别和原生后台录制尚未接入。详见 [能力边界](LIMITATIONS.md)。
